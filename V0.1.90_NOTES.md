# 0.1.90-dev

Comparison planning now decomposes explicit differ/difference/distinguish requests into two subject definition/unit tasks plus a distinction task. Meaning questions retain `mean` wording instead of being converted to measurement questions. Existing direction and location scenarios retain their paths. Previously the unrecognized generic difference request caused a fallback to one combined generation.

Per-subject source selection now retains definition and unit evidence when they come from separate passages, preserving original source IDs. A unit passage that also defines the subject is preferred to avoid adding unnecessary passages. No factual answer is hardcoded.

Validation: five Java request-trigger regex checks passed. Kotlin regression cases added for three-part planning and split-source selection. Full Kotlin tests, Android build and device generation unavailable in this environment. Generated claims and citation support still require review.

Device test: rerun the exact heat/temperature comparison. Diagnostics should now show PART 1 / 3, PART 2 / 3 and PART 3 / 3. Check heat/joule, temperature/kelvin and the distinction with supporting citations.
